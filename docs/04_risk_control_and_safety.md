# 04. 平台防封号与拟人化风控实践手册

本文档总结了 BOSS 直聘等国内招聘平台的反爬机制与风控模型，并给出了本系统采用的**全方位拟人化对抗与熔断策略**。

---

## 一、 平台核心风控机制剖析

国内主流招聘平台的风控主要从以下 4 个维度进行综合研判：

1. **环境与指纹层**：
   * 检测 `navigator.webdriver` 属性、CDP 调试特征、Chromium 补丁标记。
   * 检查 Canvas / WebGL / AudioContext 指纹是否与真实日常用户一致。
2. **行为特征层**：
   * **超人速度**：瞬移点击、极速打字（0ms 间隔）、瞬间翻页。
   * **机械化规律**：固定间隔（如每隔 5.0 秒投递一次）、无鼠标滑动直接触发 Click。
3. **业务频次与配额层**：
   * 平台对求职者有隐性/显性的“每日发起沟通上限”（通常 50~100 个/天）。
   * 短时间内连续发起 20+ 次打招呼直接触发滑块验证或临时禁言 24 小时。
4. **时间分布与异常时段**：
   * 凌晨 2:00~5:00 大批量打招呼属于典型脚本异常行为。

---

## 二、 系统的 6 重核心安全护城河

### 1. 真实日常 Chrome + CDP 挂载（攻克环境指纹）
*   **做法**：用户使用日常 Chrome，带 `--remote-debugging-port=9222` 启动并手动扫码登录。
*   **收益**：Cookies、LocalStorage、浏览器扩展、硬件渲染指纹完全与真人上网一致，从根源上规避了无头浏览器和 WebDriver 痕迹。

### 2. 贝塞尔曲线平滑鼠标轨迹 (Bezier Mouse Movement)
*   **做法**：点击按钮前，通过数学三次贝塞尔曲线算法计算从当前鼠标位置到目标坐标的非匀速移动轨迹，带有微小的过冲与修正抖动。

### 3. 拟人随机打字与阅读延时
*   **打字输入**：输入打招呼语或消息时，单字符按键延迟设定为 `random.randint(60, 160)` 毫秒，并在标点符号处额外停留 200~400ms。
*   **页面停留**：打开岗位详情页后，强制随机向下滚动 200~500px，停留 3~6 秒阅读后再点击沟通。

### 4. 每日沟通配额与时间窗口管制
*   **单日上限**：系统硬性限制单日最大打招呼次数为 **30 ~ 45 次**（远低于平台 100 次的安全红线）。
*   **运行窗口**：仅在工作日标准时段（**上午 09:30~11:30，下午 14:00~17:30**）执行批量投递，夜间仅执行低频消息监听。

### 5. 验证码实时熔断机制 (Captcha Circuit Breaker)
*   每当执行页面操作后，立即检测页面是否存在滑块验证码弹窗（如 Geetest、极验等）：
    *   **触发动作**：代码**立即暂停所有自动化队列**。
    *   **推送通知**：向飞书/手机推送高优先级警报：“检测到滑块验证码，请在电脑上完成滑动”。
    *   **人工完成后继续**：人工滑动成功后，在终端敲击回车或发送 Webhook 指令恢复运行。

### 6. 防幻觉与事实边界防护
*   在 System Prompt 中加入最高级别负向约束：
    *   *“严禁虚构任何简历中未出现的项目、学历或技能。”*
    *   *“涉及薪资谈判、联系方式确认或具体面试档期时，一律转交人工处理，严禁私自替候选人做决定。”*
