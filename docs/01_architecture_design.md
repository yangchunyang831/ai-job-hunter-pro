# 01. 系统整体架构设计与 CDP 控制规范

本文档定义了 AI Agent 智能求职系统的总体架构分层、模块协作关系、Chrome CDP 通信协议及核心数据流转规范。

---

## 二、 核心交互模块职责

### 1. CDP 控制器 (`cdp_controller.py`)
*   **通信方式**：通过 WebSocket 连接 `http://127.0.0.1:9222/devtools/browser`。
*   **双页面管理 (Dual Page Worker)**：
    *   **Worker Tab 1（岗位检索与投递）**：负责搜索页翻页、点进详情、提取 JD、点击发起沟通。
    *   **Worker Tab 2（消息监听与代聊）**：独立常驻在消息聊天页面，每 30 秒监听一次未读消息，执行多轮对话。
*   **网络拦截优先**：监听 `Network.responseReceived`，直接截取岗位列表和聊天记录的 JSON 报文，无需受限于前端 DOM 频繁改版。

### 2. 决策与打分引擎 (`scoring_engine.py`)
*   输入清洗后的 JD JSON 与标准化个人画像。
*   输出 0~100 综合分、匹配亮点标签、风险点警示以及针对性开场白。

### 3. 多轮沟通状态机 (`conversation_fsm.py`)
*   维护每个 HR 的独立对话上下文与当前对话阶段（State）。
*   根据用户配置的 `inquiry_templates.yaml` 执行渐进式追问与意图应答。

## 三、 数据持久化规范 (SQLite)

本地数据库位于 `data/job_hunting.db`，包含 3 张核心表：

1. **`jobs_history`（岗位历史表）**：
   * `job_id` (PK), `job_title`, `company_name`, `city`, `distance_km`, `salary_raw`, `min_salary`, `max_salary`, `llm_score`, `tier_level`, `status`, `created_at`
2. **`conversations`（会话记录表）**：
   * `conv_id` (PK), `job_id`, `hr_name`, `hr_title`, `current_state`, `inquiries_asked`, `inquiries_answered`, `updated_at`
3. **`chat_messages`（消息流水表）**：
   * `msg_id` (PK), `conv_id`, `sender` (HR/AI/HUMAN), `content`, `intent`, `timestamp`
