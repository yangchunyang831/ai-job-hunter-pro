# 02. 多城市空间地理与立体化筛选过滤规范

本文档详述了系统采用的**四级空间地理辐射筛选模型**、**硬性黑名单规则**以及**多维动态加权评分策略**。

---

## 一、 多城市与四级空间地理辐射模型

系统支持在 `config/cities.yaml` 中配置多个目标城市。每个城市以求职者设定的居住/理想驻地为原点锚点，建立 4 个层级的动态筛选策略：

```
                    ┌─────────────────────────────────────────┐
                    │      Tier 4: 全国优质 / 远程办公        │
                    │   (Remote 专属，或超高薪一线大厂)        │
                    ├─────────────────────────────────────────┤
                    │      Tier 3: 省内中心 / 省会城市        │
                    │   (需覆盖异地租房溢价，自研中大型)       │
                    ├─────────────────────────────────────────┤
                    │      Tier 2: 邻近核心地级市             │
                    │   (高铁/轻轨同城圈，覆盖优质产业带)      │
                    ├─────────────────────────────────────────┤
                    │      Tier 1: 10km 本地极限通勤圈        │
                    │   (家门口神仙通勤，适当放宽门槛)         │
                    └─────────────────────────────────────────┘
```

### 各层级计算与策略联动表：

| 层级 | 地理范围判断依据 | 薪资门槛浮动 | LLM 最低投递分 | 打招呼策略与优先级 |
| :--- | :--- | :--- | :--- | :--- |
| **Tier 1 (本地圈)** | 距离锚点 $\le 10\text{km}$ | 允许浮动 $-10\%$ | $\ge 75$ 分 | **最高优先级**。突出通勤便利、稳定性高。 |
| **Tier 2 (邻近市)** | 同城或邻近地级市列表 | 基准薪资 | $\ge 80$ 分 | **次高优先级**。确认通勤或提供班车情况。 |
| **Tier 3 (省内中心)**| 位于目标省份内 | 要求高于基准 $+20\%$ | $\ge 85$ 分 | **中等优先级**。必须是规模型自研企业。 |
| **Tier 4 (全国/远程)**| 标记 `远程`/`Remote` 或一线超高薪 | 要求高于基准 $+35\%$ | $\ge 88$ 分 | **特批通道**。远程岗位直接赋予最高加分。 |

---

## 二、 空间距离计算算法（Haversine 公式）

系统通过从 JD 页面解析的经纬度或地址文本，计算与配置锚点的球面直线距离：

$$\Delta\sigma = 2 \arcsin \left( \sqrt{\sin^2\left(\frac{\Delta\phi}{2}\right) + \cos(\phi_1)\cos(\phi_2)\sin^2\left(\frac{\Delta\lambda}{2}\right)} \right)$$
$$d = R \cdot \Delta\sigma \quad (R = 6371.0\text{ km})$$

## 三、 三层漏斗式筛选过滤流水线

### 1. 第一层：硬性黑名单与零 Token 过滤（耗时 < 1ms）
*   **外包公司与劳务派遣拦截**：
    *   匹配公司全称与简称（如中软、软通、佰钧成、博彦等 100+ 外包名单）。
    *   JD 关键词扫描：`外包`、`驻场`、`外派`、`劳务派遣`、`自备电脑`、`与第三方签合同`。
*   **薪资水分脱水算法**：
    *   若 $\frac{\text{MaxSalary}}{\text{MinSalary}} \ge 2.5$（如 `3k-25k`、`5k-30k`），判定为纯提成/画饼套路岗，直接丢弃。
    *   若最高薪资低于候选人设定的最低薪资底线，直接丢弃。
*   **企业规模与融资阶段**：
    *   过滤未融资且人数 $< 20$ 人的作坊型公司（除非设置白名单）。

### 2. 第二层：HR 活跃度与时效性过滤
*   **活跃标签判定**：
    *   ✅ 允许投递：`刚刚活跃`、`今日活跃`、`3日内活跃`、`在线`。
    *   ❌ 丢弃淘汰：`本周活跃`、`近1月活跃`、`半年前活跃`（僵尸岗位）。
*   **发布时间新鲜度加权**：
    *   $24\text{h}$ 内新发布岗位：优先队列加权 $+15$ 分。

### 3. 第三层：LLM 深度语义匹配（DeepSeek-V3）
*   输入候选人简历结构化画像与清洗后的 JD 文本。
*   严格按 4 个维度输出标准 JSON：
    1. **技术栈重合度 (40%)**
    2. **核心业务与项目经历相关性 (30%)**
    3. **工作年限与学历资质契合度 (20%)**
    4. **发展亮点与加分项 (10%)**
*   输出结果必须附带 **`matching_highlights`**（提炼 2 个强匹配点供后续生成定制打招呼语使用）。
